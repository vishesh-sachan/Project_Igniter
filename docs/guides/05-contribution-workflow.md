# Contributing to Project Igniter

Project Igniter is a Tauri v2 desktop app: React 19, TypeScript, Tailwind CSS 4, Zustand, and Vite, with a small Rust side for filesystem commands.

## Prerequisites

- **Rust toolchain** (stable) — required to run the desktop app: <https://rustup.rs>
- **Bun** — package manager and runtime: <https://bun.sh>

## Dogfooding note

Project Igniter bootstraps its **own** repo. The `setup.sh` / `setup.ps1` at the repo root are generated by the app itself (`bash setup.sh` runs the project's own workflow). Keep them in sync with the code as you change the converter.

## Quick setup

```bash
git clone https://github.com/<you>/project-installer
cd project-installer
bun install
bun run tauri dev
```

`bun run tauri dev` compiles the Rust side on first start, then serves the Vite frontend. The app opens a native desktop window.

## Where things live

| Area | Location |
|------|----------|
| Frontend entry | `src/main.tsx`, `src/App.tsx` |
| Pages | `src/pages/` (ProjectSelection, ProjectOverview, WorkflowBuilder) |
| Editor components | `src/features/workflow/` |
| Properties panes | `src/features/properties/components/` |
| Persistence & generation | `src/services/` |
| Converter | `src/converter/` (see `src/converter/README.md`) |
| Rust commands | `src-tauri/src/` |

## How a change flows

1. Extend the **model** in `src/features/workflow/types/workflow.ts`.
2. Add UI/edit logic in `src/features/workflow/utils/workflowUtils.ts` (recursive transforms) and the Zustand store.
3. For a **new step type**: add a case in `workflowFactory.ts`, a converter in `src/converter/steps/`, wire it into `bash.ts` / `powershell.ts`, and add a properties panel.
4. Persistence lives in `src/services/workflowService.ts`; script generation in `src/services/generateScriptsService.ts`.

## Conventions

- **Immutability** — editing utilities return new objects; they never mutate in place.
- **Pure converter** — `src/converter/` does not touch the filesystem. It returns `{ path, content }` pairs; the caller performs I/O.
- **Schema changes** — `index.schema` in `workflows.json` is bumped only on **Generate Scripts**.

## Build / typecheck

```bash
bun run build    # tsc && vite build
```

Follow the existing 2-space indent and use `type` imports for types.

## How to submit

1. Branch: `git checkout -b feat/your-change`.
2. Keep the data path consistent: model → converter → orchestrator.
3. Verify with `bun run build`, then generate scripts and run `bash setup.sh` in a scratch project to confirm the emitted code.
4. Open a PR; it will run typecheck.

For schema-level or converter-shaping changes, open an issue first to discuss migration impact.
